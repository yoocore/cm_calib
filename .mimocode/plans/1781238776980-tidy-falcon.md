# CameraCalibration 项目深度理解报告

## 项目定位

**CarMaker/IPG-MOVIE 相机标定工具链** — 半自动校准仿真摄像头安装参数，使虚拟相机画面与真实图片对齐。

核心能力：通过 DDE 通信控制 IPG-MOVIE，自动迭代调整相机参数（位置、朝向、镜头参数），基于标定板检测评分驱动优化收敛。

---

## 架构分层

```
┌─────────────────────────────────────────────┐
│  GUI 层 (gui_app/)                          │  PySide6 桌面应用，三栏布局
│  ProcessService → QProcess 调用后端脚本       │  薄封装，不含标定算法
├─────────────────────────────────────────────┤
│  编排层 (calibration_orchestrator.py)        │  多相机顺序执行
├─────────────────────────────────────────────┤
│  运行态控制层 (cmapi_testrun_control.py)     │  Vehicle 激活、TestRun 同步、
│  + DDE 健康检查 (dde_health_check.py)        │  IPG-MOVIE 启停与配置
├─────────────────────────────────────────────┤
│  核心算法层 (camera_calibration.py)          │  参数优化、FBO 抓图、
│  12,317 行，唯一真实入口                      │  标定板检测与评分
├─────────────────────────────────────────────┤
│  DDE 通信层 (pywin32)                        │  TclEval → CarMaker → IPG-MOVIE
│  Script Control 写参 + FBO 离屏抓图          │  两跳 DDE 链路
└─────────────────────────────────────────────┘
```

## 端到端工作流（5 个阶段）

### 阶段 1: 配置引导 (Bootstrap)
- 用户提供：真实相机图、标注图（红框标定板）、相机名
- `bootstrap_config_from_annotation()` 从标注图提取红框 → OCR 识别板 ID → 匹配模板原型 → 生成 `camera.<name>.json`

### 阶段 2: 前置检查 (Precheck)
- `precheck_cli.py` 验证：原图存在、配置存在、Movie 目录完整

### 阶段 3: 运行态准备 (Runtime Prepare)
- Vehicle 文件激活目标传感器
- DDE 同步 TestRun → StartSim → StopSim 初始化 CarMaker
- 启动/连接 IPG-MOVIE → 启用 Abraxas → 选择相机 → 初始化控件
- 读取当前参数值写入 config `initial` 字段

### 阶段 4: 编排执行 (Orchestration)
- `calibration_orchestrator.py` 逐个相机启动标定子进程
- 解析 stdout 前缀协议 (`CALIBRATION_PROGRESS_JSON:`, `ORCHESTRATION_EVENT_JSON:`)

### 阶段 5: 核心优化 (Optimization)
- **10 个可优化参数**: pos_x/y/z, yaw/pitch/roll, lens_fov, lens_scale, lens_offset_x/y
- **坐标下降算法**: 逐参数双向试探 → 接受/拒绝 → 多参数联合探索
- **评分体系**: 多板联合评分 + 退化约束
  - `BoardScore = a1*RMSE + a2*MaxError + a3*MissRate`
  - `TotalScore = Σ wi*BoardScore_i + λ*DegradePenalty`
- **停止条件**: target_score 达标 / max_iters=180 / min_improve 阈值

## 核心技术细节

### DDE 通信链路
```
Python → pywin32 DDE → TclEval/CarMaker → Script Control → IPG-MOVIE
```
- **写参**: 生成 Tcl 脚本，通过 DDE 写入相机 widget 值并调用 `.camera.btn.set`
- **抓图**: FBO 离屏渲染 + `gl readpixels` → 保存 PNG
- **结果**: 写入文件 → Python 轮询等待

### 标定板类型
| 类型 | 检测方法 | 模板前缀 |
|------|---------|----------|
| checkerboard | OpenCV findChessboardCorners | B-, S- |
| custom_maker | cv2.matchTemplate | C- |
| aruco | ArUco 字典检测 | A- |
| charuco | ChArUco 检测 | CH- |
| apriltag | AprilTag 检测 | AT- |

### 优化策略
1. **坐标下降**（默认）: 逐参数扰动 + 方向翻转
2. **联合探索**: 多参数同时移动（trial_multipliers [1,2,4]）
3. **策略自适应**: 根据瓶颈板重排参数顺序、调整步长
4. **多起点**: 多组扰动初始值，取最优
5. **Campaign 轮次**: 重复优化 N 轮

### GUI 状态机
`IDLE → PREPARING → READY → RUNNING → FINISHED/FAILED/STOPPED`

## 关键设计决策

1. **DDE/FBO 唯一链路** — 彻底抛弃窗口截图和 UI 自动化
2. **GUI 是 CLI 的薄封装** — 不内嵌标定算法，通过 QProcess 调用
3. **单一配置文件** — 每个 camera 只有一个 JSON，best_values 自动回写
4. **多板联合评分 + 退化约束** — 避免单板优化导致其他板恶化
5. **Portable EXE 交付** — 最终用户不依赖 Python 环境
6. **结构化 JSON 协议** — CLI 输出保持固定前缀，GUI 解析

# 总得分输出改进方案

## 问题描述

- **症状**: mk_1 检测得分 25，但总得分只有 20
- **根本原因**: 总得分是多维度加权平均，不是简单平均
- **用户体验问题**: 用户感到困惑，不知道为什么总分低于单个 board 得分

## 已完成的改进（提交 0ce03f8）

### 在日志和内部增加得分分解

**目的：** 保留详细的计算过程，便于调试，但不展示给用户

**新增字段：**
1. `best_metrics.score_breakdown` - 详细的加权贡献分解
   - 每个 board 的原始得分、权重、有效权重、加权贡献
   - 总权重、加权平均、惩罚项贡献

2. `summary.score_statistics` - 快速统计概览
   - 最小/最大/平均/中位数 board 得分
   - 最好和最差的 board ID

**在日志中打印：**
```
Score statistics: min=15.00 max=25.00 avg=19.33 median=18.00 best_board=mk_1 worst_board=mk_2
```

### 保持向后兼容
- 不改变现有的 best_score、init_score、current_score 的含义
- 不改变 GUI 的显示逻辑
- 所有新增字段都是可选的，向后兼容

## 核心问题（待解决）

**用户反馈：** "GUI上保持统一的标准，不要让用户觉得25和20对不齐"

**问题本质：**
- 用户在 GUI 上看到了单个 board 的得分（如 mk_1 = 25）
- 但也看到了总分（best_score = 20）
- 这让用户感到困惑，期望总分 ≥ 单个 board 得分
- 但实际是加权平均，总分可能低于某些单个 board 得分

**可能的解决方向：**

### 方向 1：只在 GUI 显示总分
- **做法：** GUI 只显示 best_score，不显示单个 board 得分
- **优点：** 避免用户比较不同基准的得分
- **缺点：** 用户失去了单个 board 的详细信息

### 方向 2：显示统一标准的得分
- **做法：** 给用户一个简化的评分（如 0-100 分或 A-F 等级）
- **优点：** 用户体验一致，不需要理解复杂的加权平均
- **缺点：** 可能掩盖真实问题，信息不够详细

### 方向 3：调整显示逻辑
- **做法：** 在 GUI 中不同时显示 board 得分和总分
- **优点：** 保持信息完整性，避免混淆
- **缺点：** 需要更复杂的 UI 设计

### 方向 4：改变评分标准（不推荐）
- **做法：** 让单个 board 得分和总分在逻辑上更一致
- **优点：** 从根本上解决问题
- **缺点：** 会改变整个评分系统，影响范围大

---

## 推荐方案

**采用方向 1 + 方向 3 的组合：**

1. **在 GUI 上主要显示总分（best_score）**
   - 这是用户最关心的指标
   - 避免用户比较不同基准的得分

2. **在详细信息/日志中保留 board 得分**
   - 用于调试和问题诊断
   - 不会混淆普通用户

3. **在鼠标悬停或点击时显示详细分解**
   - 满足高级用户的需求
   - 保持界面简洁
